D-06Upload chạy encrypt trước khi user bấm “Save to My documents” (gộp D-03, D-04) Mới 09/11

BugHighDone

Feedback khách hàng

Khi user upload lên chưa có vào process encrypt, khi nào user click “Save to My documents” thì lúc này mới gọi API upload document và vào process encrypt.
Tiến độ 10/11: Đã sửa: chỉ upload & encrypt sau khi user bấm Save to My documents.

Hiện tại vs. Mong muốn

Hiện tạiNgay khi chọn file (My computer / From cloud / kéo thả), hệ thống gọi API upload và encrypt luôn – file hiện trạng thái Encrypted dù user chưa bấm Save.
Mong muốnChọn file chỉ thêm vào danh sách chờ ở client (Ready). Chỉ khi bấm Save to My documents mới gọi API upload và chạy encrypt.

Ảnh hưởng

  • User bấm Cancel hoặc xoá file thì file vẫn đã nằm trên server → dữ liệu rác, tốn storage và tài nguyên encrypt.
  • User chưa kịp nhập Title / Description thì file đã xử lý xong – sai kỳ vọng của bước xác nhận.
  • Với sản phẩm bảo mật tài liệu, file lên server khi user chưa đồng ý lưu có thể gây lo ngại về quyền riêng tư.

Đề xuất xử lý

  1. Chọn file: chỉ validate ở client (PDF/DOCX/XLSX/PPTX, ≤ 50 MB), giữ File trong state, status = Ready.
  2. Sửa Title/Description, xoá file không gọi API.
  3. Bấm Save to My documents: gọi API upload (kèm title, description) → Uploading → Encrypting → Encrypted; xử lý lỗi từng file.
  4. Cancel: chỉ clear state ở client.

Acceptance criteria

  • Chọn file không phát sinh request upload/encrypt (kiểm tra tab Network).
  • Bấm Save mới phát sinh request; trạng thái hiển thị đúng tiến trình.
  • Bấm Cancel sau khi chọn file → không có tài liệu nào được tạo trên server.

Đã xác nhận với khách

  • Khi user upload file, file chỉ được giữ ở frontend – chưa gọi API, chưa lưu vào database.
  • Chỉ khi user bấm Save to My documents mới gọi API upload và chạy encrypt.

Đã gộp D-03 (Save uploaded document) và D-04 (Upload: kiểm tra encryption khi upload) vào item này.

Hiện tạiSau khi lưu tài liệu mới, badge cạnh menu My documents vẫn giữ số cũ cho tới khi reload trang.
Mong muốnBadge cập nhật ngay sau khi lưu thành công (1 → 2…), và giảm khi xoá tài liệu.

Các bước tái hiện

  • Sau khi API save thành công, refetch / invalidate query đếm tài liệu (hoặc cập nhật store dùng chung cho sidebar).

Acceptance criteria

  • Badge thay đổi ngay sau khi lưu/xoá, không cần reload.
  • Số trên badge khớp với số tài liệu trong danh sách My documents.
